## 这是什么

大部分聊天 App 是「一个 AI，一种性格」。这个项目想验证另一种做法：

- **一个 Key，多个大脑** —— API Key 只填一次，之后可以在不同伴侣身上指派不同厂商的模型（硅基流动 / OpenAI / Claude / 通义 / DeepSeek……）
- **一个应用，多个人设** —— 工作伴侣、睡眠伴侣、旅游伴侣各自有独立的系统提示词和聊天记录，互不打扰
- **数据全在本地** —— 没有账号体系、没有云端同步，聊天记录就是本地几个 JSON 文件，随时能看、能备份、能删

## 核心概念：三层结构

理解这三层，整个应用就通了。**这也是第一次使用时最容易卡住的地方**：

| 层 | 是什么 | 类比 | 数量关系 |
|---|---|---|---|
| **模型服务** | 一组连接信息：Base URL + API Key + 模型名 | 大脑 | 一个 Key 可被多个伴侣共用 |
| **伴侣** | 名字 + 头像 + 用途 + 系统提示词 + 绑定的模型服务 | 人设壳子 | 想建几个建几个 |
| **会话** | 一段聊天记录，隶属于某个伴侣 | 笔记本 | 每个伴侣各自一组，互不可见 |

聊天 = 在**某个伴侣**的**某个会话**上写字。

> **为什么模型要手动绑定，不能自动？**
> 因为一个 Key 可能同时被好几个伴侣共用，程序没法替你猜这个伴侣该用哪个。
> 所以新建伴侣时是「先选模型服务 → 再填人设」，一步绑死。
> 如果伴侣建好了才发现没绑模型，主区会给出一个「⚡ 一键绑定模型服务」按钮，点一下就能补上。

## 功能特性

### 我（使用者资料）

- **全局一份**：设置自己的头像和昵称，所有伴侣、所有会话里都用这一份
- **头像**：内置 40 个 emoji，也支持粘贴任意 emoji
- **昵称**：显示在你每条消息气泡的上方，留空则显示默认的「我」
- **伴侣知道你是谁**：昵称会被写进系统提示词，所以伴侣能直接叫出你的名字
- **随时可改**：侧边栏最底部「👤 编辑我的资料」，改完下一条消息就生效

### 伴侣（核心）

- **多伴侣**：可创建任意多个伴侣（工作伴侣 / 睡眠伴侣 / 旅游伴侣…），各自独立人设
- **模型先选后建**：新建伴侣时先挑模型服务，再填人设，一步绑定
- **自定义头像**：内置 40 个 emoji，也支持粘贴任意 emoji
- **用途说明**：自由文本，显示在侧边栏副标题，说清「TA 是干嘛的」

### 模型接入（自带 Key，界面填写）

- **9 家厂商预设**：硅基流动 / OpenAI 官方 / Anthropic Claude / Google Gemini / 通义千问（阿里百炼）/ DeepSeek 官方 / 月之暗面 Kimi / 智谱 GLM / 自定义（OpenAI 兼容）
- **选预设自动带出地址**：Base URL 和常用模型名自动填好，只需要补 Key
- **完全手填也行**：Base URL / API Key / 模型名三个字段随便填，可接任意 OpenAI 兼容服务
- **环境变量兜底**：Key 留空时自动读取同名环境变量（如 `SILICONFLOW_API_KEY`）
- **模型服务池**：同一个 Key 只填一次，多个伴侣共用；被伴侣占用时不允许删除

### 会话

- **按伴侣隔离**：点不同伴侣分别查看各自的聊天记录，互不干扰
- **自动标题**：第一条消息发出后自动取首句当标题
- **AI 起名**：点 ✨ 按钮，用该伴侣自己绑定的模型总结会话内容，生成更精炼的标题
- **手动改名**：✏️ 弹窗随时改成你喜欢的名字
- **空会话不落盘**：没聊过天的新会话不会在磁盘上留垃圾文件

### 消息

- **删单条**：每条消息下方一个 🗑 按钮，AI 答歪了直接删掉
- **批量删除**：打开「管理模式」逐条勾选，底部一键删除选中项

### 界面与体验

- **流式输出**：打字机效果，回复逐字呈现
- **主题换肤**：4 套配色（月白 / 玄夜 / 樱粉 / 天青），侧边栏一键切换；
  下拉框显示的名字**永远和页面实际颜色一致**（不存第二份状态，避免状态漂移）
- **旧数据自动迁移**：老版本 `session/*.json` 在首次启动时自动搬进新结构，聊天记录不丢

## 快速开始

### 环境要求

- **Python 3.11 或以上**
- 任意一家 OpenAI 兼容大模型服务的 **API Key**（推荐硅基流动，有免费额度）

### 安装

```bash
# 1. 下载代码
git clone https://github.com/dzkly666/Soulmate-Ai.git
cd Soulmate-Ai

# 2. 创建虚拟环境
python -m venv .venv

# 3. 激活虚拟环境
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

# 4. 安装依赖
pip install -r requirements.txt
```

### 运行

```bash
streamlit run main.py
```

浏览器会自动打开 `http://localhost:8501`。

### 首次使用（两步）

**首次使用不需要配置任何环境变量**，界面上按引导走两步就行：

1. **添加模型服务** —— 侧边栏「模型服务」区 → 选一个厂商预设 → 补上你的 API Key → 保存
2. **创建伴侣** —— 侧边栏「伴侣」区 → ➕ 新建伴侣 → 选模型、起名字、挑头像、写人设 → 完成

之后随时可以在侧边栏最底部「👤 编辑我的资料」设置**你自己**的昵称和头像。
这一份是**全局**的 —— 设一次，所有伴侣、所有会话里显示的都是它，之后想换也随时能改。

> 想用环境变量也行：Key 输入框留空时会自动读取预设对应的环境变量
> （如硅基流动对应 `SILICONFLOW_API_KEY`），不用在界面上重复填。

## 项目结构

```
.
├── main.py                    # 入口：页面配置 + 主区聊天渲染
├── sidebar.py                 # 侧边栏：主题 / 伴侣列表 / 模型服务 / 会话历史
├── dialogs.py                 # 弹窗层：新增/编辑/删除 伴侣、模型服务、会话
├── companion_manager.py       # 业务核心：伴侣、模型服务、会话的全部逻辑
├── config.py                  # 配置数据：厂商预设、emoji 清单、默认人设模板
├── theme.py                   # 主题配色：4 套配色 + 运行时切换 + 反查一致性
├── storage.py                 # 文件读写：JSON 的存 / 取 / 列 / 删
├── requirements.txt           # 依赖清单
├── README.md                  # 项目说明（本文件）
├── .gitignore                 # Git 忽略规则
├── .streamlit/
│   └── config.toml            # Streamlit 默认主题（首屏第一帧用，默认「月白」）
├── data/                      # 本地数据（自动生成，已在 .gitignore 中）
│   ├── profile.json           #   我自己的昵称 + 头像（全局一份，不分伴侣）
│   ├── providers.json         #   模型服务（含 API Key，明文存本地）
│   ├── companions.json        #   伴侣列表
│   └── sessions/<伴侣id>/     #   会话 JSON，按伴侣分目录
└── session/                   # 老版本目录（首次启动会自动迁移进 data/，可删）
```

### 分层与调用关系

```
                    ┌──────────────┐
                    │   main.py    │  入口：编排 + 主区聊天渲染
                    └──────┬───────┘
              ┌────────────┴────────────┐
              ▼                         ▼
      ┌──────────────┐          ┌──────────────┐
      │  sidebar.py  │          │  dialogs.py  │  界面层：侧边栏 / 弹窗
      └──────┬───────┘          └──────┬───────┘
             └───────────┬─────────────┘
                         ▼
              ┌──────────────────────┐
              │ companion_manager.py │  业务层：伴侣 / 模型服务 / 会话
              └──────────┬───────────┘
                         ▼
              ┌──────────────────────┐
              │      storage.py      │  文件层：JSON 存 / 取 / 列 / 删
              └──────────┬───────────┘
                         ▼
                    ┌─────────┐
                    │ data/   │
                    └─────────┘

     另有：config.py（全局常量与预设）、theme.py（主题配色）
     聊天请求：main.py → OpenAI SDK → 各家大模型 API
```

> **分层思路**：`config.py`（数据）→ `storage.py`（文件读写）→ `companion_manager.py`（业务逻辑）
> → `dialogs.py` / `sidebar.py`（界面组件）→ `main.py`（入口编排）。
> 加功能优先往对应层加，别往 `main.py` 里塞。

## 实现要点

几个当时想了比较久、值得记下来的点：

- **路径用 `os.path.dirname(os.path.abspath(__file__))` 定位** —— 换机器、换目录、从任何地方启动都不用改代码

- **按钮的回调方式要分两种**：
  普通区域用 `on_click` 回调，避免 widget 状态时序问题；
  **弹窗内**必须用 `if st.button(): ... st.rerun()` —— 因为 `@st.dialog` 底层是 fragment，
  点弹窗里的控件只会局部重跑，只有全量 `st.rerun()` 才能把弹窗关掉（这是官方文档给的唯一关法）

- **主题不存第二份状态** —— 切换时只改 Streamlit 的配置项，界面要显示"当前是哪个主题"时，
  反过来**比对服务器上真实的颜色值**推导出来（`theme.current_theme_name()`）。
  如果另外用一个变量记"当前主题名"，一旦两处不同步就会出现"下拉框写月白、页面是粉色"的 bug

- **系统提示词在发请求时现拼**（`CompanionManager.build_system_prompt`）：
  伴侣人设（含老数据 `{name}` / `{purpose}` 占位符替换）+ 当前使用者的昵称。
  昵称属于**全局资料**、不属于任何伴侣，**所以不能写进伴侣数据** —— 否则改一次名字就要把所有伴侣
  改一遍，新建的伴侣还会漏掉。现拼则永远同步

- **`OpenAI()` 每次都显式传 `base_url`** —— SDK 会自己读 `OPENAI_BASE_URL` 环境变量，
  不传的话请求可能被悄悄发到别的地方去

- **数据驱动表单** —— 厂商预设（`PROVIDER_PRESETS`）里存好地址和常用模型名，
  切换预设时自动填表，用户只需要补 Key

## 数据与隐私

- **API Key 明文保存在本机** `data/providers.json`，该目录已在 `.gitignore` 中，`git` 不会追踪它
- 本项目是**本地单用户**应用，没有登录体系 —— **请勿部署到公网**
- 界面上 Key 输入框是密码模式，列表里只回显后 4 位
- 聊天记录全部存在本机 `data/sessions/` 下，就是普通 JSON 文件，随时可看可删
- 想备份或迁移，直接拷 `data/` 目录即可

## 排错

### 1. 改完 `.py` 之后，必须重启服务器

```bash
# 在跑 streamlit 的窗口按 Ctrl+C，然后
streamlit run main.py
```

Streamlit 的「热更新」只重新执行入口 `main.py`，**不会重新 import `sidebar.py` /
`dialogs.py` / `companion_manager.py` 这些子模块**（Python 的 `sys.modules` 缓存挡着）。
所以只按 Rerun 或只刷新浏览器，用的还是内存里的旧代码，极容易误判成"改了没用"。

### 2. 界面报 `NotFoundError: Failed to execute 'removeChild' on 'Node'`（整页红框）

这不是数据出错，是**浏览器标签页的界面比服务器旧**导致的 DOM 错位。典型场景是：
标签页在服务器重启前就开着，重启后它靠 WebSocket 自动重连，但**没有整页重新加载**，
于是 React 手里的节点和新服务器发来的指令对不上，一有交互（比如点保存）就崩。

**处理办法：关掉整个标签页重开，或在页面上按 `Ctrl+Shift+R` 强制刷新**（普通 F5 有时不够）。

数据不会丢 —— 崩溃发生在"画界面"阶段，写文件已经先完成了。

### 3. 伴侣聊不了天，输入框是灰的

说明这个伴侣还没绑定模型服务。点主区黄条上的「⚡ 一键绑定模型服务」，选一个即可。

## 已知限制

- **传给模型的历史条数可在「聊天设置」里调（1~30 条）**，超出的更早上下文会被丢弃 —— 目前没有做长期记忆
- **主题切换依赖 Streamlit 的私有 API**（`st._config`），未来版本若移除需要改用其他方案
- 暂不支持插件工具与用户登录（这是设计上刻意不做的，为了让项目边界清晰）
